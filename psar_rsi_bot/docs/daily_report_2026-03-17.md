# 데일리 리포트 2026-03-17

## 오늘 작업 요약

오늘은 지난 며칠간 진행했던 Oregon 리전 이전과 멀티 컨테이너 운영 시도를 정리하고, 최종적으로 시스템 역할을 다시 정의하는 작업을 진행했다.

결론적으로:

- 서울 리전은 내가 만든 PSAR 기반 자동 주문 실행기의 **포트폴리오용 운영 서버**로 유지
- Oregon 리전은 탈개미AI 외부 전략용 멀티 컨테이너 실험 서버로만 취급
- 현재 프로젝트의 핵심 메시지는 "수익 전략"이 아니라 **운영 가능한 자동화 시스템을 구축·배포·관측·분리 운영한 경험**으로 정리

즉, 오늘은 단순 복구 작업이 아니라 프로젝트의 목적과 운영 구조를 다시 정리한 날이었다.

---

## 1. 서울 리전 정상화 완료

서울 리전 서버를 기준으로 다음 항목을 다시 확인했다.

- TradingView Webhook 수신
- 실거래 주문 실행
- Telegram 알림
- Prometheus 타깃 상태
- Grafana 접속 및 패널 확인

실제로 로컬 PowerShell에서 테스트 메시지를 전송했고, 기존과 동일하게 실거래가 정상 체결되는 것을 확인했다.

또한 Prometheus에서 `psar_rsi` 타깃이 `up 1/1`인 상태를 확인했고, Grafana와 Prometheus 모두 정상 접속되는 상태까지 복구했다.

즉, 서울 리전 기준 포트폴리오용 운영 시스템은 다시 정상 상태로 돌아왔다고 볼 수 있다.

---

## 2. Oregon 리전 운영 방향 정리

Oregon 리전에서는 Terraform 기반 멀티 컨테이너 운영을 실제로 시도했고, 탈개미AI 외부 전략 컨테이너 2개와 내가 만든 PSAR 컨테이너를 함께 운영하는 구조를 검토했다.

하지만 운영 과정에서 다음과 같은 문제가 반복되었다.

- GHCR private image 인증 문제
- Docker Compose 기동 순서 문제
- 포트 매핑 / Webhook ingress 문제
- SSM / env 반영 혼선
- 그리고 최종적으로 Binance Futures가 Oregon 리전에서 `451` 제약을 반환

이로 인해 Oregon에서 PSAR 전략까지 함께 끌고 가는 것은 실익이 크지 않다고 판단했다.

결국 오늘은 다음처럼 정리했다.

- Oregon은 더 이상 PSAR 주 운영 서버로 보지 않는다.
- Oregon은 탈개미AI 외부 전략 전용 실험/운영 서버로 한정한다.
- 당장 안정성이 떨어진다면 외부 전략은 Render 운영으로 되돌리는 선택지도 열어둔다.

추가로 정리한 판단:

- 외부 vendor 전략 2종은 Oregon에서 멀티 컨테이너로 실제 구동까지 시도했다.
- 그러나 운영 과정에서 해당 컨테이너가 Render 환경 기준으로 더 안정적으로 설계된 정황이 보여, "이전 성공"보다 "운영 적합성 검토" 경험으로 정리하는 것이 더 정확하다고 봤다.

즉, Oregon 리전 시도는 헛수고라기보다 **리전 적합성과 운영 한계를 실제로 확인한 경험**으로 정리하는 편이 맞다.

## 3. Terraform 구조 정리

Terraform은 완전히 폐기하지 않고, 다음처럼 정리했다.

- 기본 `terraform.tfvars`는 아무 컨테이너도 자동 발현되지 않도록 비활성화
- 서울 포트폴리오 서버용 예시 파일 분리
- 오리건 OKX 서버용 예시 파일 분리
- `enable_psar_container`, `enable_okx_qqq_container`, `enable_okx_xau_container` 플래그 추가

이를 통해 같은 Terraform 코드베이스를 유지하면서도 역할별 서버 구성을 다르게 가져갈 수 있는 구조를 만들었다.

중요한 점은, 지금 당장은 서울 서버를 Terraform으로 재구축하는 것이 아니라 **기존 서울 legacy 운영 서버를 유지하는 것**이 더 안정적이라는 점이다.

## 4. 문서 및 포트폴리오 메시지 재정의

오늘 문서 작업의 핵심은 과장된 수익 메시지를 줄이고, 실제로 한 운영 경험을 더 명확히 드러내는 방향으로 프로젝트 설명을 다시 쓰는 것이었다.

반영한 방향:

- 서울 / 오리건 2서버 역할 분리
- Oregon 리전 이전 및 멀티 컨테이너 운영 시도
- Binance 리전 제약 발견 후 구조 재조정
- 외부 vendor Docker 2종을 Render 외 환경으로 이전 시도했지만, 장기 유지보다는 시도와 검토 경험으로 정리
- 현재 PSAR 전략은 "핵심 수익 전략"이 아니라 "포트폴리오용 운영 증명 자산"
- 향후 MT5 기반 멀티 전략 프로젝트는 별도 트랙으로 분리 예정

즉, 현재 저장소는 "전략 자랑"이 아니라 **실무형 운영 경험을 보여주는 포트폴리오 저장소**로 톤을 재정렬했다.

## 5. 비용 관점 정리

과거에는 Render에서 전략 컨테이너를 각각 나눠 운영하며 월 약 21,000원 수준의 서버 비용이 발생했다.

이 비용을 줄이기 위해:

- 외부 전략 2종을 AWS 단일 인스턴스에 묶는 구조를 시도했고
- Terraform과 Docker Compose 기반으로 운영 재현성을 확보하려 했다

하지만 실제 운영에서는 비용만이 기준이 될 수 없었고, 거래소/리전 적합성과 안정성을 함께 고려해야 했다.

결과적으로 오늘 기준 판단은 다음과 같다.

- 비용 절감 시도는 충분히 유의미했다
- 그러나 실운영 기준에서는 "가장 싸게"보다 "안정적으로 굴러가느냐"가 더 중요했다

이 지점 역시 README와 포트폴리오 설명에 반영 가능한 운영 판단 경험이다.
